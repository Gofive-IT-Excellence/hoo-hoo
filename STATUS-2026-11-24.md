# OCR Smart Proofreader — verified status, 24 November 2026

## Integration and hosting

- Live `https://hoo-hoo.go5.online/ocr/health` returned `engine=openthai-ocr-text`, `version=2.1.4`, `status=ok`, `proofreading_ready=true`.
- Live `/proofread/health` returned `engine=local-llama.cpp`, `model=qwen3-8b`, `configured=true`.
- OpenThai Text is already the primary image OCR, packaged with Flask/Gunicorn, nginx and pinned model files in Docker on the existing company Coolify server. It is no longer only a proposal. The browser's independent Tesseract reading checks coordinates and can supply text if the server OCR fails (`script.js`).
- Spelling audits use same-origin `/ocr`, `/document/text` and `/proofread`, not Netlify Python, ngrok or the old proofreading Gateway. The separate conversational assistant still has its existing n8n integration; its current webhook health was not tested here.
- The advertised 6.6 MB / 0.39 s per page are release claims, not a measured end-to-end SLA for this deployed image.

## New evidence

The opt-in runner `tests/live-ocr-comparison.cjs` generated one 1100×650 image of six Latin labels and correct controls. Raw captures and the rendered result are saved with the task's benchmark artifacts. Compact machine-readable reports are committed under `tests/fixtures/benchmarks/2026-11-24/`.

| OpenThai request time, including HTTP | 0.493 s for this six-line image |

| Incorrect suggestion on a correct control | `Google Vids`: Vids → Vid; retained for review, not struck |
| Tesseract 5.5.3 reference | 6/6 exact; local CLI run, not previous PaddleOCR production |

Today's code preserves the complete Google Vids product name, including when the neighbouring Google token is misspelled Goegle. Replaying the SAME captured model responses through the candidate annotation code leaves only the two intended suggestions: 2 located, 0 unlocated, 0 false suggestions on the four correct controls. This is an annotation regression result, not a fresh model accuracy result.

The repository's actual poster was also sent through live OpenThai. It returned `Uอกล`, `CapCutl`, `WS!`, `Goegle Vids`, `ทำวิดีโดพรีเซนตครบ`, `ภาพ+เสียง+A`. Therefore ambiguous Thai lettering and omitted Latin characters remain unresolved; synthetic success must not certify this poster as correct. Literal Latin Ws must be kept separate from a Thai glyph misread as WS!.

## Milestone and remaining work

Integration and API hosting are complete. Validation is partial: 28 automated frontend regression cases pass, plus this small live synthetic comparison. A fixed 72% or a new completion percentage would be unsupported without agreed milestone weights.

No archived old-production PaddleOCR outputs were available for the same images, so no before/after improvement against that engine is claimed. Next validation needs a versioned, manually transcribed Thai/photo/document corpus with per-word boxes, missed-text counts, false corrections and overlay checks, plus an archived old-engine baseline. Keep the existing primary OpenThai / browser-verification arrangement while collecting that evidence rather than switch engines on six Latin labels alone.
